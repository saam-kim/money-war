# 머니워 수업 시뮬레이션 2회 검토

검토일: 2026-10-06. 대상: `sol/classroom-v2`의 현재 로컬 작업 파일.

아래 2회 검토는 원화 가치 항목을 제거하기 전의 이력이다. 사용자 승인에 따른 최신 수정과 재검증은 문서 끝의 ‘후속 수정’에 기록한다.

## 판단

두 수업 모두 개인 확인과 최종 결과까지 정상적으로 끝났다. 최초 답안 보존, 독립적인 원인·환율·원화 판단, 인과관계 해설 뒤 채점이라는 학습 구조는 유지됐다. 그러나 진행 버튼이 화면 아래로 밀리는 단계, 개인 확인 해설의 마지막 인과관계가 보이지 않는 배치, 오답 피드백의 여러 스크롤 영역 때문에 교실 사용성과 가독성은 추가 개선이 필요하다.

색·서체와 뉴스·인과관계 화면은 차분하고 현대적이다. 입력·결과 화면은 반복되는 선택 버튼과 표, 강조 표시가 많아 관리 화면의 느낌이 강하다. 새 장식이나 색을 더하기보다 정보의 우선순위와 배치를 정리하는 것이 적절하다.

## 방법과 범위

- 교사 한 화면을 투사하고 학생은 개인 종이 기록지와 모둠 답안판을 쓰는 조건이다. QR 입장, 학생 패드, 개인 계정은 평가 대상이 아니다.
- 격리된 Chrome 154 브라우저 두 개에서 가상 모둠 답안을 실제 화면 클릭으로 입력했다. Playwright로 교사 조작을 재현했으며 실제 학생이 참여한 수업은 아니다.
- 정답·부분 오답·미제출을 섞어 진행했다. 두 번째 수업은 긴 모둠 이름, 입력 정정, 타이머 종료, 새로고침, 별도 수정 기록과 생활 적용까지 포함했다.
- 각 단계의 초기 스크롤 위치에서 화면·글자 크기·진행 버튼·표와 상세 영역의 크기를 측정했다. 화면 31장을 생성하고 주요 단계 24장을 직접 시각 검토했다.
- 실행 스크립트: `tests/classroom-simulation.cjs`. 두 회차 실행 종료 코드 0. 생산용 UI 코드는 이번 검토에서 변경하지 않았다.
- 브라우저의 자동 진행 시간은 실제 수업 시간이 아니다. 실제 프로젝터, 뒤쪽 좌석, 학생 반응, 교사의 입력 시간, 학습 효과는 아직 확인하지 않았다.

## 학생 관점

### 잘 작동하는 부분

뉴스 본문 28px, 제목 38px, 핵심 해설 28px·이유 20px로 주요 학습 내용은 비교적 크게 보인다. 거래 행동 → 달러 시장 → 환율 → 원화 가치의 순서와 그래프 연결도 명확하다. 개인 판단 후 모둠 토의를 하므로 다른 모둠의 답이나 해설을 먼저 보고 따라가는 구조가 아니다.

원인·환율·원화 가치를 독립적으로 판단하고 네 요소를 나누어 채점한다. 원인을 틀렸지만 방향은 맞힌 경우와 원화 가치만 반대로 판단한 경우를 구분할 수 있다. 마지막 A/B 사례를 모둠 점수와 분리하는 것도 새 상황에 혼자 적용한다는 목표에 맞는다.

### 학습을 방해할 수 있는 부분

1. **개인 확인 A/B의 해설을 한눈에 비교하기 어렵다.** 두 사례의 본문과 인과관계를 모두 길게 배치해 1366×768과 1280×720에서 아래쪽 원화 가치까지 함께 보이지 않는다. 학생 패드를 쓰지 않으므로 교사가 스크롤하는 동안 앞 사례와 뒤 사례를 동시에 비교할 수 없다. 원인과 방향을 반복 적용하는 핵심 활동에 직접 영향을 준다.
2. **오답 이유가 작은 상세 영역에 갇힌다.** 8모둠 수업에서 여러 요소를 틀린 모둠의 상세 영역은 표시 높이 178px에 내용 262px이었다. 표에도 별도 스크롤이 있어 학생이 기다리는 동안 교사가 두 영역을 번갈아 움직여야 한다.
3. **타이머와 반복 안내가 학습 내용과 시선을 나눈다.** 타이머 64px과 단계·제목·설명이 같은 화면에서 반복된다. 타이머는 유지하되 중요도를 낮추고 중복 안내를 줄이는 편이 학습 과제에 집중하기 좋다.

## 교사 관점

### 잘 작동하는 부분

타이머 종료가 제출이나 화면 이동을 강제하지 않는다. 미제출을 기록하고 공개 전 입력을 정정할 수 있다. 해설은 교사가 단계별로 공개하고 점수는 이후 별도 행동으로 보여 준다. 새로고침 복원과 최초 답안 보존도 이번 진행에서 정상 작동했다.

### 운영 부담

1. **진행 버튼 위치가 일정하게 확보되지 않는다.** 1366×768에서 토의 안내 펼침, 수정, 개인 확인 단계의 버튼이 일부 잘리거나 아래로 밀렸다. 1280×720에서는 8모둠 최초 답안 확인, 개인 확인과 선택 활동에서 더 자주 발생했다. 예를 들어 최초 답안 확인의 하단은 944px, 수정 기록을 펼친 화면은 1302px까지 내려갔다. 일반 4단계 해설도 하단 732.5px로 720px 화면에서 조금 잘렸다.
2. **모둠 답안 입력과 진행 조작이 많다.** 기본 5모둠·6라운드에서 진행 버튼 82회, 답안 선택 87회였다. 8모둠은 모두 제출할 때 매 라운드 세 선택씩 최소 24회가 필요하다. 실제 입력 소요 시간은 측정하지 않았지만 교사가 학생 사고를 듣는 동안 반복 입력을 병행해야 하는 부담은 있다.
3. **결과표와 피드백의 여러 스크롤이 번거롭다.** 8모둠 결과표는 표시 높이 186px에 내용 730px이었다. 한두 모둠만 보이는 상태에서 모둠을 찾고 다시 상세 설명을 스크롤하게 된다. 5모둠에서도 표가 제한 높이에 갇힌다.
4. **긴 모둠 이름이 어색하게 줄바꿈된다.** 최대 길이 이름의 마지막 ‘팀’·‘조’가 한 줄에 남아 표의 리듬을 흐트러뜨린다. 모둠 번호를 기준으로 식별하면서 이름 폭과 표시 방식을 정리할 필요가 있다.

최종 결과 전체가 긴 것은 자연스러운 문서형 화면이므로 수업 중 필수 버튼이나 핵심 인과관계가 가려지는 문제보다 우선순위가 낮다. 모든 스크롤을 결함으로 판단하지 않는다.

## 디자인 판단

좋은 점은 중립색과 코발트의 제한된 사용, Pretendard의 일관된 서체, 큰 뉴스 제목, 과하지 않은 그래프다. 촌스러운 게임 장식이나 과도한 효과를 추가할 이유는 없다.

개선할 부분은 입력·결과 화면의 반복되는 사각 버튼과 ‘다시 확인’ 표시, 단계와 지시문의 중복이다. 뉴스 화면의 단정한 분위기와 달리 관리용 표의 인상이 강하다. 이는 디자인 검토자의 판단이며 실제 학생의 선호 조사 결과는 아니다. 색상 팔레트를 바꾸기보다 중요한 내용만 강조하고 반복 표식을 줄여야 한다.

## 후속 수정 · 원인과 환율 중심

사용자는 원화 가치 선택을 없애고 나머지 검토 항목을 반영하도록 승인했다. 환율 변동의 원인과 방향, 반복 적용이라는 목표와 교사 한 화면·학생 종이 기록 조건을 유지했다.

### 구현 내용

1. `js/core.js`, `js/app.js`, `js/print.js`: 원화 가치의 입력·채점·기본 해설·개인 기록 칸·결과 항목을 제거했다. 원인과 환율은 독립적으로 입력하고, 원인 카드의 시장·증감을 나누어 세 요소 각 2점으로 채점한다. 6점/라운드, 36점/24점 만점이다. 해설은 거래 → 시장 → 환율의 3단계 뒤 별도 채점한다.
2. 뉴스 공개 준비와 답안판 공개 확인의 추가 화면을 합쳤다. 뉴스 읽기 → 개인 판단 → 토의 → 모든 모둠 동시 공개 후 입력이라는 학생 행동은 유지한다. 참고 타이머는 자동 진행하지 않는다.
3. 투사 화면에서 내용과 하단 진행 영역을 별도 공간으로 나눴다. 큰 본문을 유지하면서 핵심 버튼이 밀리거나 내용을 덮지 않도록 했다. 내용 영역은 필요할 때 키보드로도 스크롤할 수 있다.
4. 개인 확인의 중복 제목과 해설의 반복 뉴스 본문을 줄였다. 두 문항 모두 푼 뒤 거래·시장·환율을 28px로 나란히 비교한다.
5. 모둠 결과표와 오답 설명을 좌우로 놓고 제한 높이 상세 스크롤을 제거했다. 여러 요소를 틀린 모둠의 설명이 함께 보인다. 결과에서 수정 단계로 이동해도 선택 모둠을 유지한다. 수정 기록은 제목 옆 버튼으로 별도 입력 공간을 열고 닫는다.
6. 반복 배지·중복 단계 안내를 줄이고 타이머를 44px로 낮췄다. 긴 모둠 이름은 투사 입력표에서 한 줄로 표시한다. 기존 팔레트·Pretendard·뉴스 28px·핵심 28px·이유 20px를 유지했다. 토의 문장 틀을 펼치면 중복 판단 안내를 숨겨 문장 전체를 보인다.
7. 저장 스키마를 v3로 변경하되 저장 위치와 탭 충돌 보호는 유지했다. v2 최초 답안은 원화 항목도 포함한 원본 그대로 보존한다. 점수에서 원화 항목을 제외하고 불러올 때 변경을 안내한다. 폐기한 단계와 해설 단계 4는 새 진행 구조로 연결한다. 수업 조건·README·교과 근거의 운영 규칙도 갱신했다.

### 같은 조건의 재실행

| 조건 | 수정 전 진행/선택 클릭 | 수정 후 진행/선택 클릭 | 최종 점수 |
| --- | --- | --- | --- |
| 5모둠·6라운드·1366×768 | 82 / 87 | 64 / 58 | 36, 36, 12, 24, 30 |
| 8모둠·4라운드·1280×720 | 57 / 85 | 45 / 57 | 24, 24, 8, 16, 18, 0, 16, 0 |

같은 원인·환율 답안 패턴을 사용하며 원화만 틀렸던 모둠은 새 기준에서 정답이다. 선택 수정 기록과 입력 정정도 해당 회차의 선택 횟수에 포함한다. 클릭 감소는 실제 수업 시간 단축이나 학습 효과 측정값이 아니다. 두 회차 모두 예상 점수와 일치하며 페이지 오류·가로 넘침·수업 중 화면 밖 진행 버튼은 없었다. 수정 전 산출물을 덮어쓰지 않고 `design/verification/cause-rate/simulation`에 새 기록을 저장했다.

핵심·그래프 17개 검사와 실제 브라우저의 8모둠·6라운드/2모둠·4라운드 전체 흐름을 확인했다. 360~1920px의 140개 배치에서 가로 넘침·그래프 라벨 잘림을 검사하고, 1280×720·1366×768에서는 전 단계 진행 영역과 개인 두 사례의 전체 표시를 확인했다. 최초 답안 보존·세 요소 부분 점수·3단계 공개·v2 복원·탭 충돌·인쇄는 별도 검사에 포함된다.

`frontend-design`, `UI UX Pro Max`의 읽기 위계·키보드·교실 배치 기준과 `Impeccable`의 기존 시각 체계 보존·Operate/Read 기준을 적용했다. 실제 학생·물리적 프로젝터·프린터 검증과 학습 효과는 여전히 미확인이다.

### 최종 기술·디자인 확인

Impeccable context는 기존 시각 구현에 대한 범위 내 개선을 허용했으며, 신규 PRODUCT.md/브랜드 생성은 수행하지 않았다. 변경된 `js/app.js`, `js/print.js`, `css/style.css`의 기계 검출 결과는 `[]`다. 주요 화면과 인쇄물을 직접 검토해 뉴스·핵심 해설의 큰 글자, 중립색/코발트 위계, 학습 내용과 진행 영역의 분리를 확인했다.

| 기술 감사 차원 | 판단 점수 / 4 | 근거와 한계 |
| --- | --- | --- |
| 접근성 | 3 | 입력 이름·fieldset·열/행 제목, 키보드 선택과 메뉴/dialog 초점 복귀, 내용 스크롤 초점. 실제 보조공학 전체 흐름은 미검증 |

| 반응형 | 3 | 140개 배치·두 투사 크기·작은 화면 실제 클릭 통과. 200% 확대와 실물 터치는 미검증 |

16/20은 제작자의 기술 감사 판단이며 학생 만족도·학습 효과·WCAG 전체 인증이 아니다. 차단 결함은 이번 범위에서 확인되지 않았다. 이전 P3인 작은 화면 최종 표의 가로 스크롤 안내는 후속 후보이며, 학생 패드를 사용하지 않는 조건에서는 실물 투사 확인을 먼저 한다.

최종 저장 검사 묶음 실행의 동시 진행 클릭이 한 번 시간 초과됐다. 실패 시 화면·버튼 진단을 추가한 독립 재실행에서는 전체 저장 검사가 종료 0으로 통과했고 재현되지 않았다. 원인은 확정하지 못했다. 자세한 최신 명령·결과는 `PROJECT_STATE.md`에 기록했다.
