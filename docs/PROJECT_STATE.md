# 머니워 진행 기록

마지막 갱신: 2026-10-07. 작업 브랜치: `sol/classroom-v2`.

## 현재 상태

최신 사용자 결정으로 생활 적용 파트를 제거했다. 뉴스 분석 → 개인 기록 고치기 → 다음 뉴스, 마지막 라운드 뒤 개인 확인 A/B → 최종 정리로 진행한다. 생활 적용 설정·화면·버튼·L/E 단축키와 관련 스타일을 제거했으며, 해당 화면에 저장된 이전 기록은 같은 라운드의 개인 기록 고치기로 복원한다.

최신 사용자 요청의 전체 여백·배치·크기 조정과 입장 화면의 별도 `수업 리허설`을 반영했다. 본문·진행 영역은 최대 1280px로 중앙 정렬하고 연습·최초 답안 확인·수업 설정은 더 좁게 묶었다. 입력표는 버튼 크기를 유지하면서 상태를 같은 행으로 정리하고 완료 수를 표 위에 표시한다. 최종 관계표와 8모둠 결과를 함께 보여준다. 교사 리허설은 5모둠·6라운드의 수정 가능한 예시 답안으로 전체 흐름을 연습하며 현재 창의 메모리만 사용한다. 실제 수업의 학생 제출 방식 연습과 구분된다.

승인된 활동·디자인 v2의 실제 정적 웹앱 구현과 로컬 검증을 마쳤다. 변경은 로컬 작업 파일에 있으며 push·운영 배포는 하지 않았다. 상위 `design` 폴더는 참조 시안 및 검증 산출물이고, 실제 실행 파일은 이 저장소의 `index.html`이다.

이후 사용자 지정 `frontend-design`, `UI UX Pro Max`, `Impeccable`로 디자인·기술 검토와 개선을 진행했다. 가장 최근에는 사용자가 원화 가치 항목 제거와 수업 시뮬레이션 피드백 반영을 승인했다. 입력·기록지·채점은 원인과 환율의 두 판단, 수요·공급·증감·환율의 세 평가 요소로 바꿨다. 6점/라운드, 기본 36점·단축 24점이며 해설은 거래 → 시장 → 환율의 3단계다. 이전 [디자인 검토](DESIGN_REVIEW.md)와 [시뮬레이션 검토](CLASSROOM_SIMULATION_REVIEW.md)의 수정 전 기록보다 최신 수업 조건과 각 문서의 후속 반영 기록을 우선한다.

투사 화면의 내용과 진행 영역을 분리해 주요 버튼을 계속 표시한다. 결과표와 선택 모둠의 오답 설명은 나란히 놓고 별도 상세 스크롤을 제거했다. 수정 기록은 제목 옆 버튼으로 입력 공간을 열고 닫는다. 두 개인 문항의 거래·시장·환율을 한 화면에서 비교한다. 뉴스 본문 28px·핵심 해설 28px·이유 20px와 기존 팔레트·서체는 유지한다. 타이머 크기와 중복 안내·반복 배지를 줄였다.

추가로 전역 수업 개발 하네스 관점에서 검토하고 사용자 후속 지시에 따라 P1/P2를 수정했다. 사용자 최신 조건은 학생 패드 미사용이며 QR·학생 입장·서버 동기화는 필요 없다. [하네스 검토 기록](HARNESS_REVIEW.md)의 오래된 탭 덮어쓰기·초기화 기록 복원은 저장 비교와 Web Locks, 최신 기록 불러오기로 보호한다. 기존 v2 기록은 최초 답안을 보존해 스키마 v3로 복원하고 6점 기준으로 다시 계산한다. 불러올 때 변경 안내를 표시하며 저장 차단 환경은 현재 창에서 진행한다.

최신 확정 기준은 저장소 안의 [수업 조건](CLASSROOM_SPEC.md), [교과서·뉴스 근거](CONTENT_SOURCES.md)와 [시뮬레이션 검토의 후속 반영](CLASSROOM_SIMULATION_REVIEW.md)이다. 상위 폴더의 `머니워_활동기획서_v1.md`, `머니워_디자인기획서_v2.md`, `SOL_개발착수.md`는 기존 설계 이력이다. 디자인 v1보다 v2, 과거의 세 판단·8점 규칙보다 최신 두 판단·6점 규칙을 우선한다. 원본 교과서 PDF와 추출 텍스트를 배포 폴더에 복사하지 않았다.

## 확정된 수업 구조

- 환율 변동의 원인과 방향을 설명하고 새 사례에 반복 적용하는 것이 핵심이다. 자산 운용·리스크 전략을 기본 기능에서 제외했다.
- 교사 화면 한 개, 2~8모둠, 6라운드/4라운드. 뉴스 읽기 → 개인 판단 → 모둠 토의 → 답안판 동시 공개 → 교사 입력으로 진행한다.
- 원인과 환율 선택은 독립적이다. 수요·공급, 증가·감소, 환율을 각 2점으로 채점한다. 원화 가치 입력·채점·별도 해설 단계는 제거했다.
- 최초 제출 전 정답·그래프·채점 색을 공개하지 않는다. 거래 행동 → 시장 → 환율의 3단계 해설 뒤 별도로 결과를 공개한다. 뉴스 준비와 동시 공개 확인의 추가 화면은 제거했다.
- 최초 답안 보존, 별도 수정 기록, 중복 채점 방지, 교사가 기록하는 미제출, 타이머 종료 시 자동 이동 없음.
- 개인 확인 두 문항은 모두 응답한 뒤 해설하며 모둠 점수와 분리한다. 생활 적용은 2026-10-07 최신 지시로 제거했다.

## 이번 재개에서 마친 작업

이전 구현 파일과 착수 지시를 대조하고 실제 앱을 끝까지 검증했다. 그래프 화살표를 이동 전·후 곡선에 연결했고, 움직이는 기존 곡선은 점선으로 구분했다. 작은 화면의 곡선 표기 위치를 수정했다.

1366×768 화면에서 뉴스·입력·해설의 진행 버튼이 화면 안에 오도록 여백과 타이머를 조정했다. 8모둠 입력은 표 내부에서 스크롤하고 진행 버튼과 겹치지 않는다. 복원 안내는 하단에 표시해 해설 영역을 밀어내지 않는다. 작은 화면은 모둠별 입력과 충분한 크기의 조작 영역을 사용한다.

개인 문항 A/B의 뉴스 번호 표시, 인쇄 표의 마지막 테두리, 개인 해설 묶음의 페이지 나눔을 수정했다. 오래된 역할·10라운드·전략 선택 안내를 현재 구현에 맞게 README에서 교체했다. 재개 가능한 테스트와 이 진행 기록을 저장소에 추가했다.

### 전체 수업 시뮬레이션 2회 · 2026-10-06

`node tests/classroom-simulation.cjs`를 실제 화면 클릭으로 실행해 종료 0을 확인했다. 5모둠·6라운드·1366×768과 긴 이름의 8모둠·4라운드·1280×720을 개인 확인과 최종 결과까지 진행했다. 정답·부분 오답·미제출을 섞은 예상 점수와 실제 점수가 일치했다. 두 번째 회차는 타이머 종료 후 교사 제어, 공개 전 입력 정정, 해설 중 새로고침 복원, 별도 수정과 생활 적용을 포함했다. 페이지·리소스 오류와 페이지 가로 넘침은 없었다.

진행 버튼 클릭은 각각 82/57회, 답안 선택 클릭은 87/85회였다. 전체 조작 수나 실제 수업 시간은 아니다. 격리된 제작자 브라우저와 가상 모둠을 사용했으며 실제 학생이나 프로젝터 검증은 아니다. 상위 `design/verification/classroom-simulation`에 JSON 측정과 화면 31장을 저장하고 주요 단계 24장을 직접 시각 검토했다. 이번에는 검증 스크립트와 기록만 추가했으며 생산용 UI를 변경하지 않았다.

이전 기본 화면 검증을 확대해 토의 안내 펼침·8모둠 최초 답안 확인·개인 확인·수정 입력까지 확인한 결과, 진행 버튼이 일부 잘리거나 화면 아래로 밀리는 경우를 발견했다. 개인 확인 A/B 해설에서 원화 가치까지 한눈에 비교되지 않으며, 결과표와 오답 상세에 별도 스크롤이 생긴다. 이는 이전 저장 보호 P1/P2와 구분되는 신규 미해결 UI 항목이다. 큰 글자를 유지하면서 필수 진행 영역, 두 사례 비교, 충분한 피드백 공간부터 수정한다. 입력·결과 화면의 반복 표식과 긴 이름 줄바꿈은 후순위로 정리한다.
