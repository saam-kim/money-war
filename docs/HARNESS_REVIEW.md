## 적용 범위와 판정

전역 `C:/Users/USER/.codex/AGENTS.md`의 수업 개발 하네스, `classroom-development/SKILL.md`와 수업 설계·교실 화면·연결과 검증·배포와 자료 참고자료를 적용했다. 확정 기획서, 현재 코드, 진행 기록, 기존 검증 증거와 대조했다.

사용자 최신 조건은 **교사 기기 하나를 투사하고 학생은 종이와 답안판으로 참여**하는 것이다. 학생 패드, QR 입장, 학생 계정, 학생/교사 간 서버 동기화는 요구사항에서 제외한다. 모바일 화면은 교사의 보조 환경이며 학생 참여 경로가 아니다. 로그인·공개 게시판·서버 권한·학생 기기 한글 입력 등의 검증은 해당 기능을 구현하지 않은 현재 범위에 적용하지 않는다.

수업 목표와 주요 활동 구조는 하네스에 부합한다. 최초 검토에서 아래 기록 충돌 문제를 우선 발견했고 후속 수정에서 해결했다. 브라우저 기능 검증과 실제 수업의 가독성·시간·학습 확인을 구분한다.

## 확인된 문제

### P1 · 오래된 탭에서 저장 기록을 덮어쓸 수 있음 — 수정 전 재현

`js/app.js`는 로드 시 저장 상태를 한 번 읽고, `save()`에서 자신의 메모리 상태 전체를 같은 localStorage 키에 쓴다. 다른 탭에서 진행·초기화한 사실을 확인하는 로직이 없다. 이 문제는 학생 기기가 없는 교사 단독 운영에서도 브라우저 중복 탭으로 발생할 수 있다.

동일 Chrome 브라우저 컨텍스트의 두 탭에서 실제 버튼으로 재현했다.

1. A 탭에서 2모둠 수업을 시작하고, B 탭은 첫 뉴스 공개 준비 상태에서 복귀했다.
2. A 탭에서 두 모둠의 세 판단을 입력·확정하고 첫 해설을 공개했다. 저장 상태는 `explanation`, 최초 답안 2개, 공개 단계 1이었다.
3. B 탭에서 다음을 누르자 저장 상태가 `newsReading`, 최초 답안 `null`, 공개 단계 0으로 돌아갔다. A 화면은 여전히 해설을 표시했다.
4. A 탭에서 초기화를 승인한 후 B 탭에서 다음을 누르면 초기화한 기록이 `individual` 단계로 다시 저장됐다.

단일 탭에서의 최초 답안 보존·중복 채점 방지 검증은 여전히 유효하다. 그 보장을 여러 탭에 확장할 수 없다는 발견이다.

권장 수정: 현재 수업 식별자와 저장 버전을 확인하고, 다른 탭이 변경한 기록에는 오래된 탭이 쓰지 못하게 한다. 충돌 시 교사에게 최신 기록에서 이어갈 수 있는 안내를 제공한다. 초기화 뒤의 오래된 탭도 기존 수업을 되살리지 못하게 한다. 답안을 자동 병합할 필요는 없으며 교사 한 탭 운영 정책이 적합하다. 수정 뒤 이 두 경로를 회귀 검증한다. 이번 요청은 검토이므로 기능 변경은 보류했다.

### P2 · 수업 근거와 확정 조건이 저장소 밖에 있음 — 수정 전 상태

교과서 근거가 없는 것은 아니다. 상위 폴더의 `머니워_활동기획서_v1.md`에 두 교과서의 인쇄 쪽수와 학습 요소 연결표가 있다. `머니워_디자인기획서_v2.md`와 `SOL_개발착수.md`도 현재 작업에서 확인했다.

그러나 저장소 안의 진행 기록은 이 외부 파일들을 기준 자료로 참조하며, `js/data.js`의 개별 뉴스에는 교과서 근거 식별자가 없다. Git 저장소만 새 기기에 가져오거나 다른 개발자에게 넘기면 확정 조건과 문항 근거를 따라가기 어렵다. 전역 하네스의 재개·근거 추적 관점에서 보완할 부분이다.

권장 수정: 저장소 `docs`에 최신 확정 수업 조건과 교과서 단원·쪽수·뉴스별 적용 관계를 정리한다. 원본 PDF나 추출 텍스트를 복사하지 않고 참고 메타데이터와 직접 작성한 요약만 남긴다. 교과서 원리와 이 앱이 만든 게임 규칙을 구분한다. 운영 화면에 긴 출처 설명을 추가할 필요는 없다.

## 수업 운영에서 남은 확인

기능 오류와 실제 교실에서 확인할 사항을 구분한다.

- **개인 학습 확인:** 앱의 총점은 모둠 선택의 결과다. 각 학생이 실제로 먼저 판단했고 거래 이유를 설명할 수 있는지는 개인 기록지와 교사 관찰로 확인한다. 개인 확인 두 문항에 거래 이유 작성란이 있다. 라운드 중에도 몇 명의 이유를 구두로 확인하고, 마지막 개인 기록을 수거해 수요 감소/공급 감소와 원화 가치 혼동을 구분하는 운영이 적합하다. 패드 제출이나 자동 개인 점수 기능을 추가할 필요는 없다.
- **수업 시간:** 20/30분은 운영 예상치다. 8모둠의 세 판단 입력은 라운드마다 최소 24회 선택이 필요하며 실제 입력 시간은 미측정이다. 첫 적용에서 입력·협의·해설 시간을 나눠 관찰하고 선택 수정 기록·생활 적용을 필요한 때만 사용한다.
- **투사 가독성:** 1366×768 배치와 해설 28px/20px는 브라우저에서 확인했다. 프로젝터의 실제 해상도·밝기·후방 좌석 거리에서 읽히는지는 미확인이다. 학생 모바일 세부 개선보다 이 확인이 우선이다.
- **출력:** Chromium A4 개인 기록지/최종 정리는 검증 기록이 있다. 실제 프린터와 필기 공간은 교실 적용 전에 확인한다.
- **배포:** 현재 변경은 로컬 미커밋 작업 파일이다. 원격 push·운영 배포·운영 페이지 확인을 완료로 표현하지 않는다. 별도 교사용 PDF 가이드·홍보자료는 요청하지 않았으므로 이번 검토의 미완료 항목이 아니다.

## 검증 근거와 한계

이번 검토는 실제 소스와 문서 대조 및 새로 발견한 다중 탭 우려의 표적 재현을 수행했다. 기존에 통과한 전체 검사를 이유 없이 반복하지 않았다.

- 기존 검증: 핵심/그래프 15개, 실제 브라우저 8모둠·6라운드와 2모둠·4라운드 전체 흐름, 138개 레이아웃 조건, Chromium A4 출력. 명령·환경·증거는 `PROJECT_STATE.md`와 `DESIGN_REVIEW.md` 참조. 이번 결과로 다중 탭 보장까지 포함하지 않음을 명확히 한다.
- 이번 실행: Node.js로 상위 `design/verification/harness-multitab.cjs` 실행, 종료 코드 0. Windows, Playwright + 설치된 Chrome headless, `http://127.0.0.1:8766`, 가상 2모둠, 동일 컨텍스트의 2탭. 위 두 **결함 재현 성공**을 뜻하며 앱이 검사에 통과했다는 뜻이 아니다.
- 제작자 테스트용 격리 브라우저 컨텍스트만 사용했다. 교사가 사용 중인 브라우저 저장 기록과 실학생 자료는 조작하지 않았다.
- 교과서 연결은 기존 기획서와 로컬 추출 텍스트의 관련 단원을 대조했다. 이번 검토에서 원본 PDF 전체를 다시 렌더하거나 모든 인용 쪽수를 재검수하지는 않았다.
- 실제 프로젝터·프린터·교사 입력 시간·개인 학습 변화·운영 배포는 미확인이다. QR 카메라·학생 패드·독립 학생 인증·서버 동시성은 현재 수업 조건에 해당하지 않는다.

## 최초 검토의 작업 우선순위

1. 다중 탭의 오래된 저장과 초기화 후 기록 복원을 방지한다.
2. 저장소 안에 수업 조건과 교과서 근거를 재개 가능한 형태로 정리한다.
3. 프로젝터·기록지·8모둠 입력 시간을 중심으로 실제 교실 리허설을 진행한다.

기존 모바일 P3는 교사 보조 화면의 낮은 우선순위 개선 사항으로 유지한다. 전역 하네스를 이유로 QR·학생 패드·새 서버 기능을 추가하지 않는다.
